This answers a different question.
It asks: who is allowed to depend on whom.
```
        Infrastructure
      ┌─────────────────┐
      │   Application   │
      │  ┌───────────┐  │
      │  │  Domain   │  │
      │  │           │  │
      │  └───────────┘  │
      └─────────────────┘
```
The domain is at the center. for example:
```
Domain (business logic (transfer/withdraw, ...) irrespective of tools used)
 ├── User
 ├── Order
 ├── Payment
 └── PricingRules
 
 # example:
 class BankAccount {
  withdraw(amount: number) {
    if (amount > this.balance) {
      throw new Error("Insufficient funds");
    }

    this.balance -= amount;
  }

  deposit(amount: number) {
    this.balance += amount;
  }
}
```
The domain shouldn't care weather you're using psql, mongo, redis, aws, http, graphql

#### application
This is the layer that coordinates the business operation. it says: what does the system need to do
example:
```
class TransferMoney {
  constructor(
    private accountRepository: AccountRepository,
  ) {}

  async execute(command: TransferMoneyCommand) {
    const from = await this.accountRepository.find<Account>(command.from);
    const to = await this.accountRepository.find<Account>(command.to);

    from.withdraw(command.amount);
    to.deposit(command.amount);

    await this.accountRepository.save(from);
    await this.accountRepository.save(to);
  }
}
```
This isn't business rule. It instead coordinates the operations

#### infrastructure
how does the application interact with the outside word
```
class PostgresAccountRepository implements AccountRepository {

  async find(id: string) {
    return db.query(...);
  }

  async save(account: BankAccount) {
    return db.query(...);
  }
}
```
Because postgres isn't the business, it can be replaced with Mongo tomorrow.  


Instead of 
```
Domain → PostgreSQL
```
You'd have
```
Domain (business logic)
  ↑
Application (collating business operations for the given logics/infrastructures)
  ↑
Infrastructure (connection to external resources )
```

for example:
```
                  PostgreSQL
                      │
                      ↓
               OrderRepository
                      │
                      ↓
                Application
                      │
                      ↓
                   Domain
```

### Layer 1: Core Domain Model (center of the onion)
	It has zero external dependencies -–– not even NestJs
```
// src/domain/models/user.model.ts
export class User {
  constructor(
    public readonly id: string,
    public readonly email: string,
    public readonly name: string,
  ) {
    if (!email.includes('@')) {
      throw new Error('Invalid email address');
    }
  }
}
```

### Layer 2: Domain Port/Interface (contract)
	The domain defines what it needs to persist data, but not how
```
// src/domain/ports/user-repository.port.ts
import { User } from '../models/user.model';

export interface IUserRepository {
  save(user: User): Promise<void>;
  findByEmail(email: string): Promise<User | null>;
}

// Token used for NestJS Dependency Injection
export const USER_REPOSITORY = Symbol('USER_REPOSITORY');
```

### Layer 3: Application Use Case (Orchestrator)

Orchestrates business flow. It depends **only** on the domain model and the abstract repository port.

TypeScript

```
// src/application/create-user.use-case.ts
import { Injectable, Inject } from '@nestjs/common';
import { User } from '../domain/models/user.model';
import { IUserRepository, USER_REPOSITORY } from '../domain/ports/user-repository.port';

@Injectable()
export class CreateUserUseCase {
  constructor(
    @Inject(USER_REPOSITORY)
    private readonly userRepository: IUserRepository,
  ) {}

  async execute(id: string, email: string, name: string): Promise<User> {
    const existing = await this.userRepository.findByEmail(email);
    if (existing) {
      throw new Error('User already exists');
    }

    const newUser = new User(id, email, name);
    await this.userRepository.save(newUser);
    return newUser;
  }
}
```

### Layer 4: Infrastructure (Outer Ring)

Here we write the actual database implementation and HTTP controllers.

#### Database Implementation (PostgreSQL, TypeORM, or In-Memory)

TypeScript

```
// src/infrastructure/repositories/in-memory-user.repository.ts
import { Injectable } from '@nestjs/common';
import { User } from '../../domain/models/user.model';
import { IUserRepository } from '../../domain/ports/user-repository.port';

@Injectable()
export class InMemoryUserRepository implements IUserRepository {
  private readonly users = new Map<string, User>();

  async save(user: User): Promise<void> {
    this.users.set(user.id, user);
  }

  async findByEmail(email: string): Promise<User | null> {
    for (const user of this.users.values()) {
      if (user.email === email) return user;
    }
    return null;
  }
}
```

#### HTTP Controller

TypeScript

```
// src/infrastructure/controllers/user.controller.ts
import { Controller, Post, Body } from '@nestjs/common';
import { CreateUserUseCase } from '../../application/create-user.use-case';

@Controller('users')
export class UserController {
  constructor(private readonly createUserUseCase: CreateUserUseCase) {}

  @Post()
  async createUser(@Body() body: { id: string; email: string; name: string }) {
    return this.createUserUseCase.execute(body.id, body.email, body.name);
  }
}
```

### Connecting Everything (NestJS Module)

NestJS glues the outer implementation to the inner contract using Dependency Injection:

TypeScript

```
// src/user.module.ts
import { Module } from '@nestjs/common';
import { UserController } from './infrastructure/controllers/user.controller';
import { CreateUserUseCase } from './application/create-user.use-case';
import { InMemoryUserRepository } from './infrastructure/repositories/in-memory-user.repository';
import { USER_REPOSITORY } from './domain/ports/user-repository.port';

@Module({
  controllers: [UserController],
  providers: [
    CreateUserUseCase,
    {
      provide: USER_REPOSITORY, // When the use case asks for USER_REPOSITORY...
      useClass: InMemoryUserRepository, // ...give it the concrete InMemory implementation!
    },
  ],
})
export class UserModule {}
```
