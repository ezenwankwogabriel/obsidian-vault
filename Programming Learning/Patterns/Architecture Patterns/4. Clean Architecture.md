Clean Architecture is extremely closely related to Onion Architecture.

The terminology differs somewhat, but the fundamental idea is:

> **Business rules shouldn't depend on frameworks, databases, or delivery mechanisms.**

You might see:

```
        Frameworks & Drivers
   ┌───────────────────────────┐
   │     Interface Adapters    │
   │   ┌────────────────────┐  │
   │   │ Application Logic  │  │
   │   │  ┌──────────────┐  │  │
   │   │  │   Domain     │  │  │
   │   │  └──────────────┘  │  │
   │   └────────────────────┘  │
   └───────────────────────────┘
```

The important rule:

**Dependencies point inward.**

So your business logic shouldn't say:

```
import { PrismaClient } from "@prisma/client";
```

if you're trying to strongly enforce Clean Architecture.

Instead:

```
interface UserRepository {
    findById(id: string): Promise<User>;
}
```

Your application logic depends on that abstraction.

Then infrastructure does:

```
class PrismaUserRepository implements UserRepository {
    ...
}
```
