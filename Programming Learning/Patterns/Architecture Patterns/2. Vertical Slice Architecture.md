Instead of organizing code by technical responsibility, organize it by business capability/feature

Instead of:
```
controllers/
services/
repositories/
```
you'd have something like
```
orders/
    create-order/
        create-order.controller.ts
        create-order.service.ts
        create-order.repository.ts

    cancel-order/
        cancel-order.controller.ts
        cancel-order.service.ts
        cancel-order.repository.ts

users/
    register-user/
        register-user.controller.ts
        register-user.service.ts

payments/
    process-payment/
        process-payment.controller.ts
        process-payment.service.ts
```
Think of each feature as a vertical slice through all the layers
```
                HTTP
                  │
          ┌───────┴───────┐
          │ Create Order  │
          ├───────────────┤
          │ Controller    │
          │ Business      │
          │ Validation    │
          │ Persistence   │
          └───────────────┘
                  │
               Database
```

```
Orders
 ├── Create Order
 │    ├── HTTP
 │    ├── business logic
 │    └── persistence
 │
 ├── Cancel Order
 │    ├── HTTP
 │    ├── business logic
 │    └── persistence
 │
 └── Get Order
      ├── HTTP
      ├── business logic
      └── persistence
```

This can be extremely nice for large applications as *everything needed to change one feature is close together*
