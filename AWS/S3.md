## Durability & Availability
Durability defines how many times an object would lost in amazon S3

Durability is same across all storage classes (above) in Amazon S3

S3 has high durability (99.99999999999 (11 9's)) of objects across multiple AZ
With 10,000,000 objects in S3, can expect on avergage a loss of a single object every 10,000 years

Availability measures how readily available a service is
This varies depending on storage class. 
all has >= 3 AZ except one zone IA which has 1 AZ

	S3 Standard has 99.999% availability => not available 53 mins a year
		used for frequently accessed data
		low latency & high throughput
		sustain 2 concurrent facility failures
		usecase for this is Big Data analytics, mobile & gaming app, content distribution

	S3 Standard-Infrequent access (s3 Standard-IA) 
		For data that's less frequently accessed, but requires rapid access when needed
		with milliseconds access and 30 days min access
		lower cost than S3 standard
		99.9% Available
		use-case is Disaster Recovery, backups
		
	S3 One Zone-Infrequent Access (S3 One Zone-IA) [single AZ]
		High durability (99.99999999999%) in a single AZ (single AZ)
		data lost when AZ is destroyed
		99.5 Availability 
		use-case: storing secondary backup copies of on-premise data or data you can easily recreate

	S3 Glacier Storage Classes
		Low cost object storage meant for archiving/backup
		pricing here includes: price for storage + object retrieval cost
		
		## S3 Glacier Instant Retrieval
			millisecond retrieval, great for data accessed once a quarter
			minimum storage duration of **90** days

		## S3 Glacier Flexible Retrieval (formerlly Amazon S3 glacier)
			Minimum storage duration of 90 days
			- Expedited (1-5 mins) retrieval time
			- Standard (3-5 hours) retrieval time
			- Bulk (5-12 hours) free
			
		## S3 Glacier Deep Archive (for long term storage)
			Gives lowest cost and minimum storrage duration of 180 days
			- Standard (12 hours)
			- Bulk (48 hours)

	S3 Intelligent-Tiering
		Small monthly monitoring and auto-tiering fee
		moves object automatically between access tiers based on usage
		no retrieval charges in s3 intelligent tiering
			Frequent Tier: default tier
			Infrequent Tier: objects not accessed for 30 days
			Archive Instant Access tier: not accessed for 90 days
			Archive Access tier: configurable from 90-700 days
			Deep Archive Access tier: configurable from 180-800 days

## Requester Pays
Generally, bucket owners pay for all Amazon S3 storage & data transfer for the bucket
If you have lots of heavy files for customer download, can configure "Request Pays bucket". 
The requester would be the one paying for download. For this to happen, the requester must be authenticated in aws

## S3 Event Notification
events such as object created, removed, restored, replication
You can set event notification to trigger when things happen, such as to generate thumbnails of images uploaded to S3. You create an Event Notification and can send it to SNS, SQS, Lambda Function

To achieve this, we create a *Resource (Access) Policy* for the destination resources. like SNS Resource (Access) Policy, SQS, ... these are IAM permissions for access

*NB*: here we don't use *IAM roles* which typically aid permissions for connections between resources, but Resource Access Policies

## S3 Event Notifications with Amazon EventBridge
You set up Events on the buckets, these events can go through the Amazon EventBridge, then set up rules to send the events to over 18 AWS services as destination. This is another way to handle events from s3

## S3 Baseline Performance
by default s3 is free
you get at least 3,500 put/copy/post/delete or 5,500 get/head requests pers second per prefix in a bucket

S3 transfer acceleration increases transfer speed by transferring file through an AWS edge location which will forward the data to the s3 bucket in the target region. prioritizing "Private" network transfer

S3 Byte-Range Fetches
Parallelize GETs by requesting specific byte ranges
This is better for resilience in case of failures
use-case:
	- Used to speed up downloads. get them in bytes, more like streaming, but in parallel
	- to retrieve only partial data (example the head of a file)

## S3 Batch Operation
Performing bulk operation on existing s3 objects with a single request. ex:
- modify object metadata
- copy object btw s3 buckets
- Encrypt un-encrypted objects
- to modify ACLs, tags
- to restore objects from s3 glacier, ...
A job consist of a list of objects, the action to perform, and optional parameters
We use S3 batch ops as it helps manage retries, tracks progress, sends completion notification/generate reports

*can use s3 inventory to get object list and use athena to query and filter your objects* then pass to batch operation for processing

## S3 MFA Delete
forces users to generate a code on a device (mobile/hardware) before doing important operation on S3
Required for dangerous operations: 
- permanently deleting an object
- Suspend versioning on bucket
But not for:
- enabling versioning, list deleted versions

*To use MFA delete, versioning must be enabled on the bucket*

Only the bucket owner/root account can enable/disable MFA delete. 

Once setup, you cannot delete a bucket from the aws console, only from cli

For this, you'd need to do so from the CLI (this is like permissions for doing things outside of the aws console)
- Create a profile
- setup mfa delete for the profile
- command to disable also
```
aws configure --profile root-mfa-delete-demo
// input access key and secret
// aws s3 ls --profile root-mfa-delete-demo
aws s3api put-bucket-versioning --bucket xxxx --versioning-configuration Status=Enabled,MFADelete=Enabled --mfa "xxx" --profile root-mfa-delete-demo // enable mfa delete
aws s3api put-bucket-versioning --bucket ..... MFADelete=Disabled ... --profile ... // disable mfa delete
```

## S3 Object Lock (versioning must be enabled)
- Adopt a WORM model
- Block an object version deletion for a specified amount of time
- can object lock on a single object

	Retention Period: protects an object until a specified date. (ex: keep a fin record protected for 7 years). The object cannot be permanently deleted before the rentention expires

	Retention modes:
	- *Compliance*: 
		- Cannot be overwritten by anyone including the root owner
		- retention modes cannot be changed/retention periods shortened
		- NObody can override rule during the retention period
	- *Governance*:
		- Most users can't overwrite/delete an object version/alter its lock settings
		- some users have special permissions to change retention/delete project
		- Think a manager can override rule with special authorization
	Legal Hold: 
	- Locks the object indefinitely until an authorized user explicitly removes the legal hold. 
	- It has no automatic expiry date

## S3 Access Points

This is a named entry point to an S3 bucket, with its own access policy.
Imagine one large s3 bucket used by 1k users across serveral teams(finance, sales, analytics, ...)
Analytics team needs read access, upload service needs write access.
Instead of trying to manage every access pattern through one complicated bucket policy, you can create separate access points for diff applications/teams
Multiple access points can point to the same bucket, but each can have its own permissions/ntw control

Each AP has:
- its own DNS name (internet origin or vpc origin)
- an access policy (similar to bucket policy) to manage security at scale


## S3 Object Lambda
Use AWS lambda functions to change the object before it is retrieved by the caller application. For this you need an S3 access point. 
Connect the S3 AP to a lambda function > S3 object Lambda access point > analytics application
Use-cases: 
	redacting personally identifiable information (PII) for analysis/non-prod env
	converting across data formats (XML to JSON)
	resizing and watermarking images on the fly
